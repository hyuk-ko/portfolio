소개

정답이 없는 문제에서
판단의 기준을 먼저 설계하는
엔지니어입니다.

웹툰 서비스(버블탭)에서 캐릭터 챗봇으로 피벗하는 시기에 AI팀에 합류해, 신규 챗봇의 LLM 핵심 기능을 초기부터 설계했습니다. 지금은 캐릭터 페르소나 챗봇 버블챗·팅글에서 RAG 설계, LLM 비용 최적화, 응답 품질 자동 평가를 맡고 있으며, 직접 배포·운영하기보다 기능을 연구·설계하고 PoC로 검증해 개발팀 구현으로 잇는 역할입니다.

실시간 채팅이라는 제약 안에서 품질·비용·안정성의 균형을 찾는 데 집중합니다. 프롬프트 구조 설계부터 RAG, 비용 최적화, 자동 평가까지 제품에 직접 닿는 LLM 문제를 폭넓게 다뤄 왔습니다.

널리 알려진 기법도 도메인 특성에 따라 유효하지 않을 수 있다고 믿습니다. 직접 실험으로 검증하고 불필요한 스택을 덜어내는 방식으로 문제의 병목을 찾습니다. "좋은 대화"처럼 정답이 없는 문제 앞에서는 평가 기준을 먼저 정의하고, 휴먼 평가와의 상관계수로 그 기준 자체를 검증해 의사결정의 근거를 만들어 왔습니다.

주요 프로젝트

버블챗 ↗ 팅글 ↗
Problem

캐릭터 챗봇은 장기적 관계 형성이 핵심인데, 단순 슬라이딩 윈도우로는 오래된 대화가 통째로 잘려나갔습니다. 유저 입장에선 "내가 저번에 말했잖아"가 통하지 않는 챗봇이 됩니다.

Challenge

캐릭터 챗의 구어체 대화는 "오늘 기분 어때?" 같은 문장이 모든 대화와 의미론적으로 유사하게 나옵니다. 텍스트 매칭 계열 기법이 이 도메인에서는 전반적으로 유효하지 않다는 것을 직접 실험으로 확인했습니다.

Approach

과거 대화를 의미 단위로 청킹·임베딩해 벡터 인덱스로 구축하고, 실시간에는 임베딩 유사도 검색으로 관련 맥락을 찾아 프롬프트에 주입했습니다. 텍스트 매칭 계열 하이브리드도 시도했으나 구어체 도메인에서 효과가 없어, 임베딩 유사도 검색 기반으로 단순화했습니다.

Result

슬라이딩 윈도우 밖으로 잘려나가던 과거 대화를 검색해 참조하는 응답이 가능해졌습니다. 컨텍스트 한계로 불가능했던 수개월 전 대화 회상을 0→1로 기능화한 사례입니다.

Learned

범용적으로 알려진 청킹, 임베딩 방법도 도메인 특성에 따라 유효하지 않을 수 있습니다. 직접 실험으로 검증하고 기술 스택을 줄여나간 것이 오히려 성능 개선으로 이어졌습니다.

Problem

사용자 증가와 창작 영역 확장으로 프롬프트가 무거워지면서 채팅당 LLM 비용이 가파르게 증가했습니다. 단순 트래픽 증가가 아닌 구조적 문제였습니다.

Challenge

프롬프트가 여러 영역의 조합으로 구성되어 유저마다 다른 조합을 사용합니다. 캐싱은 내용 변경 시 즉시 무효화되기 때문에 영역 배치 순서가 히트율의 핵심 변수였습니다.

Approach

프롬프트를 변경 빈도에 따라 영역별로 분리해 독립 캐싱 적용. 불변 영역을 상단에, 가변 영역을 하단에 배치하는 구조로 재설계했습니다. API 장애·타임아웃 시 대체 모델로 자동 전환하는 폴백 로직도 함께 구축했습니다.

Result

채팅당 LLM 비용 최대 45% 절감. 트래픽이 늘어도 비용이 선형으로 증가하지 않는 구조를 만들었습니다.

Learned

비용 최적화 문제가 결국 프롬프트 구조 설계 문제로 귀결됐습니다. LLM 엔지니어링에서 아키텍처적 사고가 얼마나 중요한지 체감한 케이스입니다.

Problem

텍스트만 오가는 대화는 몰입감에 한계가 있었고, 상황에 맞는 캐릭터 이미지가 자동으로 등장하는 기능이 전혀 없었습니다.

Challenge

한 이미지에 여러 키워드가 얽혀 있어 단일 유사도 점수로 매칭을 판단하기 어려웠습니다. 매칭 실패의 원인이 검색 모델에 있는지, LLM의 키워드 생성에 있는지부터 특정해야 했습니다.

Approach

창작자 키워드 임베딩 인덱싱 → LLM 키워드 생성 후 임베딩 유사도 매칭. UI 안내 개선을 시도했으나 한계가 있어, 창작자 패턴을 분석해 LLM 키워드 생성 프롬프트를 조정하는 방향으로 전환했습니다.

Result

내부 평가 지표 기준 매칭 정확도 +20%p 개선.

Learned

검색 품질 문제가 항상 검색 모델의 문제는 아닙니다. 생성 프롬프트 튜닝이 더 효과적인 해결책이 된 케이스로, 문제의 병목이 어디에 있는지 정확히 파악하는 것이 중요했습니다.

Problem

단일 프롬프트로 여러 국가를 운영하면 언어·문화별 어조와 금기, 콘텐츠 규제 차이를 담지 못합니다. 동시에 캐릭터 챗봇 특성상 탈옥(jailbreak)과 부적절한 콘텐츠 생성 리스크를 시장마다 다른 기준으로 막아야 했습니다.

Challenge

"안전하게 막을수록 대화가 딱딱해지고, 자연스럽게 풀수록 안전성이 약해지는" 품질과 안전성의 트레이드오프가 핵심이었습니다. 게다가 시장별로 그 균형점이 달랐습니다.

Approach

한국/태국/일본/대만 각 시장 특성에 맞춘 시스템 프롬프트를 분리 설계하고, 탈옥 방지·콘텐츠 필터링·응답 품질 개선 지침을 계층적으로 구성했습니다. 정성·정량 지표를 함께 본 A/B 테스트로 프롬프트 변경의 효과를 검증하며 점진적으로 고도화했습니다.

Result

시장별로 어조와 안전 기준이 분리된 프롬프트 체계를 운영하게 됐고, A/B 테스트를 통해 품질과 안전성을 동시에 끌어올리는 변경만 선택적으로 반영하는 의사결정 루프를 만들었습니다.

Learned

프롬프트 개선은 감이 아니라 측정으로 결정해야 한다는 것을 체감했습니다. 트레이드오프가 있는 문제일수록 정성·정량을 함께 보는 평가 루프가 의사결정의 근거가 됩니다.

Problem

자체 LLM 구축을 위한 학습 데이터 품질 검증 과정에서, 캐릭터 챗 응답의 "좋은 대화"를 수치로 정의하는 기준 자체가 없었습니다.

Challenge

정성적인 대화 데이터를 정량적으로 평가하기 위한 루브릭 프롬프트 작성이 핵심 난제였습니다. 평가 모델이 없는 상태에서 균일한 데이터 분포도 확보해야 했습니다.

Approach

캐릭터 일관성, 맥락·기억, 언어 품질, 형식·기술, 세계관·씬 준수 5가지 루브릭 기준 설계 → 휴먼 평가 후 Greedy Max-Entropy Selection으로 점수대별 균일 분포 데이터셋 구축 → 다양한 closed LLM과 프롬프트 조합 실험으로 휴먼 평가와 높은 상관계수를 달성하는 조합 선정.

Result

"좋은 대화"의 기준이 없던 상태에서 루브릭이라는 기준을 만들고, 휴먼 평가와의 상관계수로 그 기준을 검증했습니다. 학습 데이터 품질 검증을 사람 개입 없이 일관된 기준으로 수행하는 체계가 됐습니다.

Learned

캐릭터 챗봇에서는 유저의 취향과 상황에 따라 적합한 LLM이 매번 달라, 흔한 벤치마크 점수 순위와 일치하지 않을 수 있습니다. 그래서 큰 틀의 평가 기준을 확실히 잡고 일관되게 평가하는 것이 중요했고, 이를 위해 루브릭 기반의 휴먼 평가와 균일한 데이터셋 구성이 필요했습니다.
