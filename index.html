버블탭 · 2024 · RAG

RAG 기반 챗봇
장기 기억 시스템

컨텍스트 길이 초과로 오래된 대화를 기억 못하는 문제를 해결한 동적 기억 검색 시스템 설계

기억 · 검색 +
서비스 스크린샷 영역 — 추후 추가 예정
Problem

캐릭터 챗봇은 장기적 관계 형성이 핵심인데, 단순 슬라이딩 윈도우로는 오래된 대화가 통째로 잘려나갔습니다. 유저 입장에선 "내가 저번에 말했잖아"가 통하지 않는 챗봇이 됩니다.

Challenge

캐릭터 챗의 구어체 대화는 "오늘 기분 어때?" 같은 문장이 모든 대화와 의미론적으로 유사하게 나옵니다. BM25·TF-IDF 등 텍스트 매칭 계열 기법이 이 도메인에서는 전반적으로 유효하지 않다는 것을 직접 실험으로 확인했습니다.

Approach

클로바 문맥 API 기반 의미 단위 청킹 → 코사인 유사도 검색 → BM25 하이브리드 시도 → Reranker 추가 → 최종적으로 텍스트 매칭 계열을 제거하고 Reranker + 코사인 유사도 조합으로 정리했습니다.

Result

수개월 전 대화를 자연스럽게 이어받는 응답이 가능해졌습니다. "챗봇이 나를 기억한다"는 사용자 체감이 정성적으로 개선됐습니다.

Learned

범용적으로 알려진 기법도 도메인 특성에 따라 유효하지 않을 수 있습니다. 직접 실험으로 검증하고 기술 스택을 줄여나간 것이 오히려 성능 개선으로 이어졌습니다.

버블탭 · 2024 · RAG · 이미지 검색

캐릭터 이미지
매칭 RAG

대화 상황에 맞는 캐릭터 이미지를 자동 발화하는 시스템 — 임베딩/리랭커 기반 매칭 정확도 20%p 개선

+20%p 정확도 +
서비스 스크린샷 영역 — 추후 추가 예정
Problem

텍스트만 오가는 대화는 몰입감에 한계가 있었고, 상황에 맞는 캐릭터 이미지가 자동으로 등장하는 기능이 전혀 없었습니다.

Challenge

창작자가 입력한 이미지 설명 키워드(예: "웃음")와 LLM이 생성한 상황 키워드(예: "웃는 상황이었다") 간의 표현 스타일 격차가 유사도 비교를 어긋나게 했습니다.

Approach

창작자 키워드 임베딩 인덱싱 → LLM 키워드 생성 후 코사인 유사도 비교 → Reranker 추가. UI 안내 개선을 시도했으나 한계가 있어, 창작자 패턴을 분석해 LLM 키워드 생성 프롬프트를 조정하는 방향으로 전환했습니다.

Result

내부 자동 평가 지표 기준 매칭 정확도 +20%p 개선. 대화 흐름에 맞는 이미지가 자연스럽게 등장하며 캐릭터 몰입감이 높아졌습니다.

Learned

검색 품질 문제가 항상 검색 모델의 문제는 아닙니다. 생성 프롬프트 튜닝이 더 효과적인 해결책이 된 케이스로, 문제의 병목이 어디에 있는지 정확히 파악하는 것이 중요했습니다.

버블탭 · 2024 · 비용 최적화

LLM 비용 최적화
& 폴백 체계

영역별 캐싱 전략과 프롬프트 구조 재설계로 채팅당 LLM 단가 최대 45% 절감

-45% 비용 +
서비스 스크린샷 영역 — 추후 추가 예정
Problem

사용자 증가와 창작 영역 확장으로 프롬프트가 무거워지면서 채팅당 LLM 비용이 가파르게 증가했습니다. 단순 트래픽 증가가 아닌 구조적 문제였습니다.

Challenge

캐릭터/세계관/씬 세 영역의 조합으로 프롬프트가 구성되어 유저마다 다른 에셋 조합을 사용합니다. 캐싱은 내용 변경 시 즉시 무효화되기 때문에 배치 순서가 히트율의 핵심 변수였습니다.

Approach

프롬프트를 영역별로 분리해 독립 캐싱 적용. 불변 영역(캐릭터, 세계관)을 상단에, 가변 영역(씬, 최근 대화)을 하단에 배치하는 구조로 재설계했습니다. API 장애·타임아웃 시 대체 모델로 자동 전환하는 폴백 로직도 함께 구축했습니다.

Result

채팅당 LLM 비용 최대 45% 절감. 트래픽이 늘어도 비용이 선형으로 증가하지 않는 구조를 만들었습니다.

Learned

비용 최적화 문제가 결국 프롬프트 구조 설계 문제로 귀결됐습니다. LLM 엔지니어링에서 아키텍처적 사고가 얼마나 중요한지 체감한 케이스입니다.

버블탭 · 2024 · 평가 자동화

LLM 응답 품질
평가 체계 구축

자체 LLM 구축을 위한 자동화 평가 파이프라인 — 루브릭 설계부터 엔트로피 기반 데이터셋 구축까지

평가 · 자동화 +
서비스 스크린샷 영역 — 추후 추가 예정
Problem

자체 LLM 구축을 위한 학습 데이터 품질 검증 과정에서, 캐릭터 챗 응답의 "좋은 대화"를 수치로 정의하는 기준 자체가 없었습니다.

Challenge

정성적인 대화 데이터를 정량적으로 평가하기 위한 루브릭 프롬프트 작성이 핵심 난제였습니다. 평가 모델이 없는 상태에서 균일한 데이터 분포도 확보해야 했습니다.

Approach

캐릭터 일관성, 맥락·기억, 언어 품질, 형식·기술, 세계관·씬 준수 5가지 루브릭 기준 설계 → 휴먼 평가 후 Greedy Max-Entropy Selection으로 점수대별 균일 분포 데이터셋 구축 → 다양한 closed LLM과 프롬프트 조합 실험으로 휴먼 평가와 높은 상관계수를 달성하는 조합 선정.

Result

자동화된 평가 파이프라인으로 학습 데이터 품질 검증을 사람 없이도 일관되게 수행할 수 있는 체계를 구축했습니다.

Learned

많은 closed LLM이 생각보다 휴먼 평가와 상관관계가 낮았습니다. 좋은 평가 시스템은 좋은 모델이 아니라 좋은 기준에서 나온다는 것을 배웠습니다.
